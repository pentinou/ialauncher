1 Moteur d'inférence

Le launcher pilote llama-server (projet llama.cpp), le programme qui charge le modèle et répond aux requêtes. Il doit être compilé pour votre matériel (CUDA pour NVIDIA, Metal pour Mac, Vulkan/ROCm pour AMD…).

2 Modèle

Un modèle est un fichier .gguf : ses poids déjà quantifiés (compressés). Plus le fichier est gros, plus il est intelligent… et plus il faut de mémoire. Choisissez-en un déjà présent, ou téléchargez-en un.

Où va la mémoire ?

Sélectionnez un modèle pour voir la répartition prévue entre la VRAM (mémoire de la carte graphique, la plus rapide), la RAM (mémoire centrale, 5 à 20× plus lente pour un GPU) et le SSD (là où dorment les fichiers, et d'où llama.cpp relit ce qui ne tient pas en RAM).

3 Réglages

Configuration automatique — le launcher part de l'idéal (tout sur le GPU) et ne sacrifie que le nécessaire, dans l'ordre le moins coûteux.

5 Outils de code : Claude Code, Codex, OpenCode

  
Ces agents parlent à un serveur de modèle par une API. llama-server expose nativement les trois dialectes qu'ils attendent (/v1/messages pour Claude Code, /v1/responses pour Codex, /v1/chat/completions pour OpenCode) : il suffit de leur dire où est le serveur, par des variables d'environnement au lancement — aucun de vos fichiers de configuration n'est modifié. Un agent a trois exigences : un modèle qui sait appeler des outils (lire, écrire, exécuter), un contexte long (le seul prompt système de Claude Code fait ~15 000 jetons, et tout l'historique est renvoyé à chaque tour) et un traitement du prompt rapide (c'est ce qui domine, plus que la génération).
